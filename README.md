# PetAccess 手机网页交互原型

在线体验：https://Angie-oss111.github.io/petaccess/

代码仓库：https://github.com/Angie-oss111/petaccess

部署方式：GitHub Pages 从 `main` 分支根目录发布，更新并推送网页文件后会自动重新部署。

打开 `index.html` 即可体验；网页不依赖安装或构建。所有图片已保存在 assets 文件夹，可以离线打开。电脑宽屏显示品牌介绍和手机预览，手机上自动铺满屏幕。

体验路径：

1. 在发现页搜索地点，按大型犬、露台、水碗等条件筛选，切换地图示意。
2. 免费遛狗地按宠物友好公园、郊野步道、公共开放绿地、携宠公共空间分类。详情展示范围、路面、饮水与携宠规则，支持本机打卡和纠错；免费点位不提供预约、交易或广告。咖啡馆单独展示套餐。
3. 点击底部悬浮 AI 入口，选择示例问题或输入文字，查看“携宠散步 → 咖啡”路线。
4. 从免费点位选择“只逛免费地点”或“散完步，再喝杯咖啡”。免费路线仅展示公共点位；新规划按全部同行宠物的种类、体型、出行方式、门店接待数量与本机打卡状态筛选，现场变化点位暂不推荐。可替换地点、保存行程，在行程页查看。已保存路线遇到状态变化会显示提示。
5. “人宠好套餐”独立展示咖啡馆提供的双人下午茶，列明餐饮、携宠服务、门店和价格；门店详情展示同一套餐。当前套餐不含宠物餐食。预约套餐，选择到店日期和时间，记录演示预约；在“我的”中查看或取消。
6. “我的”支持添加、编辑、移除多只宠物档案，兼容原先单宠档案。狗狗记录体型，猫咪选择猫包 / 航空箱、胸背牵引或暂不外出。可勾选多只本次同行宠物，路线同时检查全部同行条件；猫咪接待未确认的点位不进入携猫推荐，猫包要求独立判断。“更多筛选”支持猫包友好条件。
7. 每只宠物可记录过敏状态（尚未确认 / 暂无已知过敏 / 已知过敏原）、多项过敏原、补充说明及照护偏好。已知过敏必须至少选择一项或填写补充说明。
8. 预约时重新勾选实际到店宠物，显示不符合接待条件的原因，并检查门店宠物数量上限。默认不附带过敏与照护信息；主动勾选本次授权后，仅所选宠物的照护资料会附带至本机演示预约。“门店接待信息预览”可在成功页和历史预约中查看。此处没有真实同步、商家账号或发送接口。
9. 历史预约保存当时的宠物及授权信息快照，之后修改或删除档案不会改写历史记录。保存的路线保留当次同行组合，后续对照这些宠物的最新接待条件显示提示。

边界：这是用于讨论和验证产品方向的前端原型。商家、点位规则、距离、评价、价格与库存均为示例，图片为氛围素材。地图为本地 SVG 交互示意，AI 为本地规则模拟；没有接入真实模型、地图导航、定位、支付或商家订单。不产生实际扣费或商家预约。收藏、宠物档案、行程、打卡纠错及演示预约通过 localStorage 保存在当前浏览器。

建议后续开发：真实宠物友好点位与规则核验、商家维护入口、账号与多宠档案云端存储、明确授权范围的商家照护信息同步及门店确认、基于点位库的 AI 检索与路线计算、实时库存、订单及支付、UGC 多用户存储、审核和规则更新（当前打卡仅为本机演示，未接入 Agent 知识库）。

图片来源：Unsplash（已本地保存）。

视觉版本：奶油白 × 深海蓝 × 杏黄色。主色 `#254F5D`，底色 `#F8F6F1`，点缀 `#F0C678`。统一了卡片、标签、导航、AI 对话和预约页样式，并扩大输入框及图标按钮的触控区域。

图片加载：6 张示例照片已压缩为 WebP 并内嵌在 `app.js`，页面不再单独请求照片，避免首次部署或网络波动出现图片留白。原始 JPG 保留在 `assets/`。替换图片后运行 `python3 scripts/bundle_images.py`（需要 Pillow），同时更新 `index.html` 的脚本版本号，再提交发布。
