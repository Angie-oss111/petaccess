# PetAccess 手机网页交互原型

在线体验：https://angie-oss111.github.io/petaccess/?v=27

代码仓库：https://github.com/Angie-oss111/petaccess

部署方式：GitHub Pages 从 `main` 分支根目录发布，更新并推送网页文件后会自动重新部署。

打开 `index.html` 即可体验；网页不依赖安装或构建。所有图片已保存在 assets 文件夹，可以离线打开。电脑宽屏显示品牌介绍和手机预览，手机上自动铺满屏幕。

体验路径：

1. 在发现页搜索地点，按犬只体型、猫包、多宠数量、指定室内区、露台、遮阴、围栏、饮水和距离组合筛选，切换地图示意。
2. 免费遛狗地按宠物友好公园、郊野步道、公共开放绿地、携宠公共空间分类。详情展示范围、路面、饮水与携宠规则，支持本机打卡和纠错；免费点位不提供预约、交易或广告。咖啡馆与餐厅分别展示套餐，首页入口可切换免费遛狗地、咖啡馆、餐厅、商场及套餐，并可返回全部地点。
3. 点击底部悬浮 AI 入口，选择示例问题或输入文字，按同行宠物、套餐预算、距离、时长与设施偏好，查看“散步 → 咖啡”“散步 → 餐厅”或纯免费路线。结果显示匹配依据；没有两处合适点位时明确提示调整条件，不强行推荐。自然语言支持示例关键词和数字预算，并非开放式模型理解。
4. 从免费点位选择“只逛免费地点”、“散完步，再喝杯咖啡”或“散完步，再一起吃顿饭”。免费路线仅展示公共点位；新规划按全部同行宠物的种类、体型、出行方式、门店接待数量与本机打卡状态筛选，现场变化点位暂不推荐。可替换地点、保存行程，在行程页查看。已保存路线遇到状态变化会显示提示。
5. “人宠好套餐”独立展示咖啡馆的双人下午茶和餐厅的双人午晚餐，列明餐饮、携宠服务、门店和价格；门店详情展示同一套餐。当前套餐不含宠物餐食。预约套餐，选择到店日期、时间、人数及套餐份数，金额实时更新，份数不足时提示调整。记录演示预约；在“我的”中查看或取消。
6. “我的”支持添加、编辑、移除多只宠物档案，兼容原先单宠档案。狗狗记录体型，猫咪选择猫包 / 航空箱、胸背牵引或暂不外出。可勾选多只本次同行宠物，路线同时检查全部同行条件；猫咪接待未确认的点位不进入携猫推荐，猫包要求独立判断。“更多筛选”支持猫包友好条件。
7. 每只宠物可记录过敏状态（尚未确认 / 暂无已知过敏 / 已知过敏原）、多项过敏原、补充说明及照护偏好。已知过敏必须至少选择一项或填写补充说明。
8. 预约时重新勾选实际到店宠物，显示不符合接待条件的原因，并检查门店宠物数量上限。默认不附带过敏与照护信息；主动勾选本次授权后，仅所选宠物的照护资料会附带至本机演示预约。“门店接待信息预览”可在成功页和历史预约中查看。此处没有真实同步、商家账号或发送接口。
9. 历史预约保存当时的宠物及授权信息快照，之后修改或删除档案不会改写历史记录。保存的路线保留当次同行组合，后续对照这些宠物的最新接待条件显示提示。

10. 地点详情增加四组宠物专属标签：接待宠物、可用区域、设施和到访须知。所有场所数据仍为待核验示例。
11. 地点详情可填写本人到访评价：评分、日期、同行宠物、体验标签、10–500 字感受与一张照片（JPG / PNG / WebP，最大 5 MB，压缩后保存）。本机评价单独统计，不混入示例评分；可在“我的到访评价”查看或删除。同行记录仅保存宠物名字及物种，不公开过敏信息；存储不足时保留草稿并提示重试。
12. 保存行程同时保留当时的偏好和同行组合，之后调整预算不会改写历史路线。免费线路无交易或广告，替换点位同样受偏好和宠物条件约束。

13. AI 对话输入框增加随界面语言切换的语音输入：点击麦克风后通过浏览器的 SpeechRecognition / webkitSpeechRecognition 转文字，先检查或修改再发送。可手动结束，支持自动结束、实时转写与原有文字追加；离开对话或切到后台会结束本次识别。仅在支持该接口的安全连接浏览器中可用；语音服务可能需要联网、系统设置及权限，部分内置浏览器不支持。识别由浏览器提供方处理，本站不保存录音。不支持、拒绝权限、无麦克风或网络故障时显示提示，可改用键盘听写。

14. 首页“今晚，带它一起吃饭”或 AI 中提出直接用餐需求，可体验完整晚餐流程：首次创建 / 确认宠物档案，复用本机长期记录，按物种、体型、同行数量、距离、预算和设施偏好匹配最多三家餐厅。新增两家示例餐厅；猫包和多宠规则继续生效，不足三家时如实展示。过敏记录用于提醒与授权照护预览，不代表已核验菜品或交叉接触风险。
15. 餐厅详情增加排队查询与演示取号，展示 200 桌在前、约 400 分钟的示例估算。本机保留一个进行中的等位号，支持刷新恢复、主动取消、到达结束；过敏与照护信息仅勾选授权后附带本次快照，未发送给门店。存储失败不显示取号成功。
16. 取号后可展开宠物友好地图，点击公园、饮水点、拾便垃圾桶、周边咖啡厅查看说明；公园按取号时的宠物组合与本机可用状态匹配。20 分钟散步环线、设施点位、8 分钟返回路线均为本地示意，未核验夜间照明及开放状态。点击“演示推进排队”可从 200 桌推进至 12 桌、5 桌，触发网页内提醒，再进入返回路线与到达完成页。没有真实商家接口、定位、实时队列、后台推送或地图导航；重新打开网页可查看已保存在本机的状态。

边界：这是用于讨论和验证产品方向的前端原型。商家、点位规则、距离、示例评分、价格与库存均为示例；本人填写的到访评价仅本机可见，尚无公开 UGC 或到店认证，图片为氛围素材。地图为本地 SVG 交互示意，AI 为本地规则模拟；没有接入真实模型、地图导航、定位、支付或商家订单。不产生实际扣费或商家预约。收藏、宠物档案、行程、出行偏好、到访评价与照片、打卡纠错、等位号及演示预约通过 localStorage 保存在当前浏览器。

建议后续开发：真实宠物友好点位与规则核验、商家维护入口、账号与多宠档案云端存储、明确授权范围的商家照护信息同步及门店确认、基于点位库的 AI 检索与路线计算、实时库存、订单及支付、UGC 多用户存储、审核和规则更新（当前评价和打卡均为本机演示，未接入 Agent 知识库）。

图片来源：Unsplash（已本地保存）。

视觉版本：奶油白 × 深海蓝 × 杏黄色。主色 `#254F5D`，底色 `#F8F6F1`，点缀 `#F0C678`。统一了卡片、标签、导航、AI 对话和预约页样式，并扩大输入框及图标按钮的触控区域。

图片加载：6 张示例照片已压缩为 WebP 并内嵌在 `app.js`，页面不再单独请求照片，避免首次部署或网络波动出现图片留白。原始 JPG 保留在 `assets/`。替换图片后运行 `python3 scripts/bundle_images.py`（需要 Pillow），同时更新 `index.html` 的脚本版本号，再提交发布。

17. 首次使用不生成默认宠物：可自由浏览，通过首页提示、“我的”宠物档案、AI 推荐、预约或餐厅取号添加狗狗/猫咪。AI 与预约在保存后自动继续原请求；支持跳过和返回。仅清理未确认且未修改的旧“豆包”示例，保留用户保存的档案及历史记录。

18. 新增“商场”分类，以“商场目的地 → 楼层商户”展示 2 个虚构商场、7 家场内商户。商场详情分别介绍公共携宠区域、物种/体型/数量限制、入口、电梯、饮水与清洁设施；楼层与接待状态可组合筛选，进入商户后返回保留筛选和位置。明确区分指定室内可进、仅露台可进、暂不接待和规则待确认；公共区允许进入不代表商户允许进入。
19. 其中 3 家可携宠餐饮店接入现有搜索、分类、套餐预约及推荐，标明所属商场与铺位号。预约和推荐同时检查商场与商户规则；暂不接待/待确认商户只展示目录信息，不提供携宠预约或推荐。商场本身不作为套餐或免费遛狗点位；支持收藏与本机到访评价。地图默认展示商场级目的地，店名搜索可直接找到所在商场及具体餐饮店。建筑图为本地 SVG 示意，所有商场、店铺、规则和设施均为虚构待核验示例。

20. 首页顶部提供简体中文 / 粵語 / English 语言选择，当前选项高亮并保存在当前浏览器。三种语言覆盖完整产品文案：地点与店铺名称、商场楼层商户、详情与携宠规则、筛选、宠物档案表单、AI 推荐、路线、套餐预约、等位地图及提醒。粤语采用繁体字与粤语表达，英文采用对应英文名称。英文和粤语名称均可搜索，底层地点 ID、筛选值与历史记录保持稳定；用户填写的宠物名字、品种、备注、评价和自由输入原样保留。不使用外部翻译服务。
21. 语音识别语言跟随选择（普通话 zh-CN、粤语 zh-HK、英语 en-US），实际支持以浏览器语音服务为准。AI 演示支持三种语言的用餐、咖啡、免费散步等关键词及数字预算、距离、时长偏好，仍为本地规则模拟，并非开放式多语言模型理解。
